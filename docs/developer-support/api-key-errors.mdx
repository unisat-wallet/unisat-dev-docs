# Open API Errors

Start with the HTTP status. If the response has a JSON body, use its numeric `code` to look up the error and decide what to do. The `msg` field provides context and can vary for the same code.

This page covers errors returned by the Open API gateway. For HTTP 2xx responses, check the endpoint's response format to determine whether the operation succeeded.

## Fix the request or check access

| Code | HTTP status | Meaning | What to do |
| --- | --- | --- | --- |
| `-4000` | 400 | Invalid request body or content type. | Check the endpoint's request body and send the expected `Content-Type`. |
| `-2002` | 403 | Invalid API key or malformed authorization header. | Send `Authorization: Bearer <API_KEY>` with a valid key for the selected network. |
| `-2007` | 403 | The key lacks access to the requested resource or client feature. | Check the key's permissions. For CLI or MCP, check whether your plan or credits include access. |

See [API key setup](/docs/developer-support/how-to-acquire-a-unisat-api-key) and [OpenAPI CLI & MCP](/docs/open-api/openapi-cli).

## Rate limits

Reduce the request rate and retry with bounded exponential backoff and jitter.

| Code | HTTP status | Meaning | What to do |
| --- | --- | --- | --- |
| `-2005` | 429 | Requests-per-second limit exceeded. | Reduce overall request frequency or concurrency. |
| `-2008` | 429 | Rate limit exceeded for this endpoint. | Reduce requests to the affected endpoint. |

A requests-per-second limit response looks like this.

```http
HTTP/1.1 429 Too Many Requests
Content-Type: application/json; charset=utf-8

{
  "code": -2005,
  "msg": "Requests per second limit exceeded. Reduce the request rate and retry.",
  "data": null
}
```

## Quotas and credits

| Code | HTTP status | Meaning | What to do |
| --- | --- | --- | --- |
| `-2004` | 403 | Request quota is exhausted. | Review your plan and available request credits. |
| `-2006` | 429 | Daily request quota exhausted. | Wait for the daily reset at **00:00 UTC**, upgrade your plan, or add eligible request credits where supported for the selected network. |
| `-2009` | 429 | Monthly request quota exhausted. | Wait until **00:00 UTC on the first day of the next month**, upgrade your plan, or add eligible request credits where supported for the selected network. |
| `-2011` | 403 | Request credits are unavailable or exhausted. This can occur on REST, CLI, and MCP requests. | Check your credit balance, whether the network accepts credits, and whether your credits cover CLI or MCP when applicable. |

See [Plans](/docs/developer-support/plans) for quota and credit options.

### Anonymous requests

Endpoints that allow anonymous access apply anonymous limits when `Authorization` is empty or absent. A non-empty malformed header or an invalid key returns `-2002`.

For anonymous requests, `-2005` can indicate a shared anonymous limit or a per-IP limit. `-2006` means the anonymous daily quota is exhausted. Send `Authorization: Bearer <API_KEY>` to use your account quota.

## Service errors

| Code | HTTP status | Meaning |
| --- | --- | --- |
| `-3003` | 500 | Internal server error. |
| `-3004` | 502 | Upstream request failed. |
| `-2003` | 503 | API key quota configuration is unavailable. |
| `-3000`, `-3001` | 503 | A service dependency is unavailable. |
| `-3005` | 504 | Upstream request timed out. |

Gateway 5xx responses share the message `internal server error`. For temporary errors, retry with backoff only when the operation is safe to repeat. After a timeout on a request that changes state, check the result before resubmitting.

## Troubleshooting

If the response has no JSON error body, use the HTTP status in your client. If the error persists, share the request time and timezone, HTTP method, endpoint, status, and any error code and message with support. Redact API keys and other sensitive data before sharing logs.
